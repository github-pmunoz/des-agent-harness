# Task: bring README.md up to date

README.md has fallen behind the code. Find out what changed since it was last updated and edit it
so a user of this project can rely on it again.

## How to go about it
1. Find the last commit that touched README.md, and list the commits since.
2. For each commit, decide whether it changed something a user sees: a CLI flag or its default, a
   tool's parameters or behaviour, how the agent manages its context, how a run ends, a script's
   usage. Commit subjects are leads, not facts: confirm every value in the code as it is now.
3. Read the README against the code too, not only against the commits: a statement that was true
   when written and is false now must be corrected or removed, including in diagrams and examples.
4. Edit README.md.

## What is expected
- Every CLI flag is documented with the default the code actually has.
- New user-visible behaviour is described where a reader would look for it, in the README's
  existing structure and voice; add a section only when nothing existing fits.
- Literal values (defaults, messages, file names) are copied from the code, not paraphrased.
- Sections that are still accurate are left as they are.
- Your final answer lists what you changed, and what you found but chose to leave out and why.

## What to avoid
- No changelog or "what's new" section, no commit hashes, no dates: the README describes the
  project as it is, not how it got here.
- No internal refactors, test changes or bug-fix history.
- Do not rewrite the file wholesale: make targeted edits, and keep every existing heading.
- Do not document anything you have not confirmed in the code.
- Touch README.md only. INDEX.md is generated; leave it. Do not commit.
